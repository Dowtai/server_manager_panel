# AWG Panel

Самостоятельная панель AmneziaWG 3.1: Go API, PostgreSQL, worker, React/TypeScript и Telegram через общий API. Реализация находится здесь; исходный Python-бот не изменяется.

Поддерживаются независимые instances, пулы Ubuntu VPS, объединение placements `all_servers` / `selected_servers`, реплики, права и лимиты устройств на уровне instance, повторная выдача только `vpn://`, отзыв, журнал операций и ручное DNS-переключение. `limit = 0` означает отсутствие квоты пользователя. Каждому устройству нужен отдельный ключ; пропускная способность VPS и адресное пространство конечны.

**Статус:** локальные тесты приложения и интеграционные тесты PostgreSQL выполнены. Runtime, импорт в реальные клиенты, подключение на Ubuntu VPS, DNS-переключение и восстановление после перезагрузки требуют испытаний из [docs/acceptance.md](docs/acceptance.md). Контейнеры нельзя считать проверенными только по сборке Go и веба. Действующая VPN-инфраструктура автоматически не импортируется и не переустанавливается.

## Установка из клона без ручной настройки .env

На Ubuntu 22.04/24.04/26.04 amd64 клонируйте этот репозиторий, перейдите в его каталог и выполните:

```sh
sudo ./install.sh
```

Установщик спросит логин и пароль администратора, HTTPS-порт (по умолчанию 443), домен и email для Let's Encrypt. Домен должен иметь A-запись на IP управляющего VPS; TCP 80 и выбранный порт панели должны быть доступны извне. Порт 80 используется для ACME-проверки и продления сертификата, поэтому портом панели быть не может. Некорректную AAAA-запись удалите, либо настройте IPv6 отдельно.

Docker и Compose устанавливаются автоматически, Go/Node на хост не нужны. Панель и AWG runtime собираются локально, runtime сохраняется в `.installer/runtime.tar` и передаётся на VPN-серверы через закреплённое SSH-соединение. Docker Hub аккаунт и публикация собственного образа для этой установки не нужны.

Caddy получает доверенный сертификат, обслуживает `https://домен` либо `https://домен:порт` и автоматически продлевает сертификат. Установщик подтверждает готовность только после успешного запроса по HTTPS с проверкой сертификата и имени домена. Закрывать TCP 80 после установки нельзя. Состояние ACME и сертификаты сохраняются в volume `caddy_data`.

`.env` генерируется автоматически с правами 0600. Открытый пароль не сохраняется: только bcrypt-хэш. При повторном запуске используются прежние секреты, настройки администратора и runtime; после исправления DNS/firewall достаточно снова выполнить `sudo ./install.sh`. Существующие конфигурации, созданные вручную, и чужие Compose override-файлы не перезаписываются. Если конфигурация потеряна, но БД/volumes остались, установщик требует восстановить её из копии, а не создавать несовместимые ключи.

```sh
docker compose ps
docker compose logs -f api worker caddy
```

Автоматически созданный `compose.override.yml` подключает HTTPS и архив runtime к обычным командам `docker compose`. Серверные порты и облачный firewall установщик не перенастраивает. Если TCP 80 занят существующим Nginx/Apache или другим контейнером, установка остановится с объяснением; эти службы автоматически не останавливаются.

Подробности: [docs/installation.md](docs/installation.md).

## Ручной запуск для разработки или существующего registry

Этот вариант нужен при собственном reverse proxy/registry. Для обычной установки используйте `install.sh` выше.

Требуется управляющий Ubuntu amd64-хост с Docker, Compose, `/dev/net/tun`, доступом к VPS по IPv4 и registry для этого ручного режима. Worker запускает отдельный клиентский контейнер для проверки рукопожжатия и трафика. PostgreSQL и API не должны быть доступны из интернета напрямую; веб публикуется через HTTPS reverse proxy.

1. Соберите runtime один раз и опубликуйте в доступном registry:

   ```sh
   docker build --platform linux/amd64 -t registry.example.org/awg-runtime:3.1 -f deploy/runtime/Dockerfile deploy/runtime
   docker push registry.example.org/awg-runtime:3.1
   docker image inspect registry.example.org/awg-runtime:3.1 --format '{{index .RepoDigests 0}}'
   ```

   Запишите полученное `repository@sha256:…` в `AWG_RUNTIME_IMAGE`. В режиме registry worker отвергает изменяемые теги. В режиме установщика используется Docker image ID и локальный архив. Registry должен быть доступен контроллеру и VPS. Для private registry сначала настройте `docker login` на обоих; панель не распространяет registry-токены.

2. Скопируйте `.env.example` в `.env`, сгенерируйте секреты и bcrypt-хэш:

   ```sh
   cp .env.example .env
   go run ./cmd/check
   # Скопируйте три выведенных значения в .env; храните ENCRYPTION_KEY отдельно от БД.
   openssl rand -hex 32
   # Результат запишите в POSTGRES_PASSWORD.
   read -s ADMIN_PASSWORD
   export ADMIN_PASSWORD
   go run ./cmd/check password
   unset ADMIN_PASSWORD
   ```

   Хэш запишите в `ADMIN_PASSWORD_HASH='…'`, сохранив одинарные кавычки: внутри bcrypt есть `$`. Логин задаётся `ADMIN_USERNAME` (по умолчанию `admin`), пароль — от 12 до 72 байт. Для production задайте `PUBLIC_URL=https://panel.example.org` и `INSECURE_COOKIE=false`. `SESSION_KEY` и `SERVICE_TOKEN` должны различаться. Для локального доступа допустимы `http://localhost:8080` и `INSECURE_COOKIE=true`.

3. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs -f api worker
   ```

   API применяет миграции goose до приёма запросов. Worker начинает работу после успешной проверки API. Откройте `PUBLIC_URL` и войдите с заданными логином и паролем.

4. Создайте пул, сервер и instance в вебе. Первый релиз работает с Ubuntu amd64, root-доступом, SSH-паролем или незашифрованным приватным SSH-ключом. Отпечаток SSH обязателен: получите его через доверенную консоль VPS (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`) и сверяйте при добавлении. Сервер и VPN endpoint имеют отдельные адреса.

5. Назначьте instance пулу или выбранным серверам. Панель покажет последствия до применения. Worker проверит маршруты, Docker-сети и UDP-порт, установит Docker при необходимости, загрузит закреплённый образ и применит полную конфигурацию. В облачном firewall разрешите выбранный UDP-порт. Контейнеры используют собственные network namespaces, `/dev/net/tun`, `NET_ADMIN` и `NET_RAW`.

6. Дождитесь статуса «Готова»: это означает успешное применение и отдельную проверку AWG-рукопожатия и HTTPS-трафика через туннель с контроллера. Создайте A-запись домена в Aéza, откройте «Endpoint и DNS» и подтвердите её кнопкой проверки. При нескольких/посторонних A/AAAA-адресах цель не подтверждается. DNS проверяется системным recursive resolver; это не проверка всех authoritative NS или кэшей клиентов.

7. Создайте пользователя, привяжите числовой Telegram ID (можно заранее), выдайте grant на instance и лимит. `0` — без квоты, положительное число — максимум активных устройств пользователя в этом instance. Пример: разные лимиты одному пользователю для Personal и Friends.

8. Создайте устройство, дождитесь новой синхронизации и получите `vpn://`. Создание и скачивание — разные операции. Повтор создания с тем же `request_id` возвращает то же устройство. При отзыве недоступная реплика остаётся неготовой до применения актуальной ревизии.

## Telegram

Укажите `TELEGRAM_BOT_TOKEN`, затем:

```sh
docker compose --profile telegram up -d telegram
```

Команды: `/instances`, `/newkey`, `/devices`, `/profile ID`, `/revoke ID`. Бот принимает запросы только в личном чате, использует идентификатор отправителя Telegram и отдельный `SERVICE_TOKEN`. Публичный запрос с одним `X-Telegram-ID` не аутентифицирован. Бот не обращается к PostgreSQL; offset хранится атомарно в volume `telegram`. Сообщение с профилем отправляется с защитой пересылки, но Telegram не обеспечивает end-to-end шифрование для ботов.

Grant разрешает **создание**. Снятие grant сохраняет существующие устройства и возможность повторного получения профиля. Для отзыва используйте отдельное действие либо флаг «Также отозвать». Блокировка пользователя прекращает доступ к API и скачиванию; VPN-peer отзывается только при выбранном действии отзыва.

## DNS и удаление

В первой версии API DNS-провайдеров нет. Выберите готовую реплику, вручную измените A-запись в Aéza и проверьте её в панели. Ключи instance и устройств остаются прежними. Клиенту может понадобиться переподключение; текущие TCP/NAT-сеансы не реплицируются.

Удалить текущую целевую реплику нельзя: сначала переключите endpoint и подтвердите DNS. Чтобы полностью вывести из эксплуатации последний instance, остановите выдачу, отзовите устройства и используйте действие очистки endpoint, описанное в API. Затем удалите placements, дождитесь удалённой очистки и удалите сервер/instance из учёта. Управление старыми контейнерами Python-бота не выполняется.

## Разработка и проверки

```sh
go test -race ./...
go vet ./...
go build ./cmd/...
cd web
npm ci --ignore-scripts --no-audit --no-fund
npm run build
```

Для интерактивной разработки `npm run dev`; настройте `PUBLIC_URL=http://localhost:5173` для проверки Origin. Go API запускается через `go run ./cmd/api` с экспортированными переменными `.env` и `DATABASE_URL`. `.env` автоматически читает Compose, а не Go.

Интеграционный тест требует отдельную пустую БД, применяет миграции и удаляет тестовые записи после завершения:

```sh
TEST_DATABASE_URL='postgres://user:pass@localhost:5432/awgpanel_test?sslmode=disable' make integration
```

Он проверяет реальные транзакции PostgreSQL, изоляцию квот между экземплярами API, сохранённые request IDs, новую ревизию во время SSH, отзыв при недоступной реплике и восстановление истёкшей операции после перезапуска. VPS в нём заменён тестовым исполнителем. SQLc-файлы генерируются `make generate` (sqlc 1.31.1); миграции встроены в бинарник.

## Резервные копии и переход

```sh
scripts/backup.sh /secure/backup/directory
scripts/verify-restore.sh /secure/backup/directory/awg-panel-YYYYMMDDTHHMMSSZ.dump
python3 scripts/inventory_legacy.py /absolute/path/to/legacy.sqlite > inventory.json
```

Последний скрипт открывает SQLite только для чтения, исключает SSH/VPN-секреты и не соединяется с VPS. В старой схеме приватные ключи клиентов не сохраняются: прежний профиль восстановить из public key нельзя. Переход выполняется отдельно по [docs/migration.md](docs/migration.md).

`ENCRYPTION_KEY` резервируйте отдельно в защищённом хранилище. Восстановление одного дампа без этого ключа не восстановит управление и клиентские профили. [docs/operations.md](docs/operations.md) описывает восстановление и обновление.

## Ограничения первой реализации

- Подсети — private IPv4 `/24`; `.1` занят сервером, `.254` проверочным peer. Активные и отозванные адреса не переиспользуются, чтобы недоступная реплика не спутала старое устройство с новым. Квота `0` не отменяет конечность подсети (252 пользовательских адреса за срок жизни instance).
- Политика firewall пула ограничивает SSH источники. Она не очищает чужие цепочки и не управляет firewall провайдера. Docker публикует UDP-порты; учитывайте его собственные цепочки и проверьте UFW/nftables на целевых VPS. Правила SSH сохраняются в отдельном systemd unit и восстанавливаются до запуска сети после reboot.
- Соединение к VPS — root по IPv4. Операции выполняются с таймаутом 10 минут, пятью попытками и ручным повтором после исчерпания. Медленная первичная установка Docker может потребовать повтор.
- База хранит отдельные сущности и ограничения ссылочной целостности; JSONB содержит их версионируемые данные. Записи одного изменения сериализуются транзакционной advisory-блокировкой, а worker использует отдельную блокировку instance. Текущий repository читает всю административную модель на транзакцию; крупным инсталляциям потребуется постраничный API и выборочные запросы.
- API не зависит от локального Docker. Worker использует Docker socket для проверочных контейнеров, поэтому доступ к worker эквивалентен административному доступу к управляющему хосту. Не размещайте его на недоверенной машине.
- Проверка из сети контроллера не доказывает доступность из сети каждого пользователя. Доставку/импорт `vpn://` и реальные клиенты проверяют отдельно.
- Runtime обновляется отдельным проверенным выпуском. Автоматическая смена image digest существующих контейнеров не выполняется.

Точные runtime refs и основания формата профиля — в [deploy/runtime/UPSTREAM.md](deploy/runtime/UPSTREAM.md).
