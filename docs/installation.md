# Интерактивная установка

## До запуска

Поддерживается Ubuntu 22.04, 24.04 и 26.04 amd64 с root/sudo, systemd и `/dev/net/tun`. Это установка на управляющий VPS, который затем управляет VPN-серверами по SSH. Серверу нужен доступ к репозиториям Ubuntu/Docker, базовым контейнерным образам и официальным исходникам AWG.

В DNS создайте A-запись `panel.example.org` на публичный IPv4 этого VPS. Домен панели может отличаться от доменов VPN instances. Панель не должна следовать переключениям VPN endpoint. Если есть AAAA-запись, IPv6 также должен обслуживаться корректно; неподдерживаемую AAAA-запись уберите.

Разрешите входящий TCP 80 и выбранный HTTPS-порт в firewall хостинга/ОС. Сохраните свой SSH-доступ. Установщик не меняет UFW и firewall провайдера и не останавливает чужие веб-серверы.

## Запуск

```sh
git clone <URL-репозитория-с-панелью> awg-panel
cd awg-panel
sudo ./install.sh
```

Вводятся:

1. Логин администратора: 3–64 ASCII-символа, буквы/цифры и `_.@-`.
2. Пароль и подтверждение: 12–72 байта, ввод скрыт.
3. HTTPS-порт панели: по умолчанию 443. Например, 9443 даст адрес `https://panel.example.org:9443`. TCP 80 зарезервирован для ACME.
4. Домен без схемы, пути и порта, например `panel.example.org`; IDN задаётся в punycode.
5. Email для ACME и подтверждение выпуска сертификата Let's Encrypt.

Установщик автоматически устанавливает Docker/Compose, если они отсутствуют, собирает панель и AWG runtime, создаёт конфигурацию и запускает PostgreSQL, API, worker и Caddy. Локальная сборка занимает несколько минут. Go и Node на хост не устанавливаются, собственного registry не требуется.

Caddy автоматически получает и устанавливает сертификат. Установка считается завершённой после запроса к API через HTTPS с проверкой доверия и доменного имени. Проверка соединяется с локальным Caddy; доступность выбранного порта из пользовательских сетей зависит от firewall/маршрутизации.

## Что сохраняется

| Объект | Назначение |
|---|---|
| `.env`, режим 0600 | Логин, bcrypt-хэш, параметры запуска и автоматически созданные секреты |
| `.installer/runtime.tar`, режим 0600 | Локальный образ AWG для передачи по SSH без registry |
| `compose.override.yml` | Подключение HTTPS и runtime-архива к стандартному Compose |
| Volume `postgres` | База данных |
| Volume `caddy_data` | Сертификаты, приватные TLS-ключи и ACME-аккаунт |
| Volume `caddy_config` | Состояние Caddy |

`.env`, `.installer` и созданный override исключены из Git и Docker build context. Пароль в открытом виде не записывается. Сохраняйте конфигурацию/ключ шифрования вместе с процедурой резервирования БД, а копии храните защищённо.

## Повторный запуск и ошибки

Повторите `sudo ./install.sh`, если DNS/firewall были исправлены после неудачной выдачи сертификата. Настройки администратора, пароль PostgreSQL, ключ шифрования и runtime сохраняются. Caddy продолжает попытки выпуска/продления самостоятельно; повторный запуск не удаляет его состояние.

```sh
docker compose ps
docker compose logs --tail=100 caddy
docker compose logs --tail=100 api worker
```

Если TCP 80 занят Nginx/Apache, либо порт панели опубликован другим приложением, установщик объяснит конфликт и остановится. Освободите порт самостоятельно или используйте ручной вариант с собственным reverse proxy. Автоматической остановки чужих сервисов нет.

Если найден ручной `.env`/пользовательский override, установщик не перезаписывает его. Если БД уже существует, но `.env` потерян, восстановите исходную конфигурацию. Создание нового ENCRYPTION_KEY не расшифрует прежние VPN/SSH-секреты.

## Продление и обновление

Для автоматического продления Caddy должен работать, DNS — указывать на управляющий VPS, TCP 80 — оставаться доступным. Дополнительный certbot/cron не нужен. Для выбранного нестандартного порта используется HTTP-01 на TCP 80; TLS-ALPN challenge отключён.

Для обновления приложения сохраните резервную копию, обновите исходники и повторите `sudo ./install.sh`. Установщик собирает новое приложение, но сохраняет runtime, его ключевые настройки и данные. Заменять runtime нужно отдельно после испытаний совместимости.

Не выполняйте `docker compose down -v` при обычном обновлении: команда удаляет persistent volumes.

Реальное получение сертификата требует публичного домена и доступного Ubuntu VPS. Локальные тесты установки не являются подтверждением выпуска сертификата на инфраструктуре пользователя.
