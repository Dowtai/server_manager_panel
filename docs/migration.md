# Отдельный переход с Python-бота

План реализации не разрешает удалять прежние контейнеры и перевыпускать действующие профили автоматически. Новый namespace `/opt/awg-panel` и контейнеры `awgp-*` отделены от `/opt/awg-bot`.

1. Снять резервную копию SQLite, volume и старого ключа Fernet. Старый бот пока продолжает обслуживать пользователей.
2. Получить инвентаризацию `scripts/inventory_legacy.py`. Скрипт работает только с локальной SQLite и не выводит секреты. Проверить VPS, порты, подсети, список пользователей и активных peer.
3. Для каждой установки выбрать: сохранить серверную VPN-идентичность с отдельным проверяемым импортом ключевого материала либо создать новый instance и выдать новые профили. Автоматического импорта секретов в текущем выпуске нет; нельзя копировать ciphertext Fernet в AES-GCM поля новой системы.
4. Старые клиентские private keys в известной схеме SQLite отсутствуют. Если нужна повторная выдача через новую систему, потребуется новый device/profile, либо отдельный безопасный импорт сохранённого у пользователя профиля. Public key не восстанавливает private key.
5. Профили с буквальным IP не начнут следовать DNS. Выдайте доменный профиль на новом тестовом instance и проверьте целевые клиенты.
6. Настройте пользователей и grants заново на уровне instance. Не переносите глобальный ACL как неявный доступ ко всем будущим instances.
7. Проверьте подключение, отзыв, резервирование и DNS по матрице приёмки. Остановите генерацию в старом боте на время окончательного переноса.
8. Только после отдельно согласованного окна удаляйте старые peer/контейнеры и отключайте старый бот. При ошибке новый instance можно снять с размещения; старую инфраструктуру до окончания окна сохраняйте для отката.
